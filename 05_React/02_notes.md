# React Tooling: npm, Vite, and ES Modules

These notes cover the tools that turn a collection of React files into an application you can develop and build for production.

## 1. npm

**npm** is the standard package manager commonly used with Node.js. It lets you install packages, manage dependencies, and run project scripts. Packages are published to the npm registry.

Think of the registry as a package catalogue; npm is the tool you use to install and manage those packages in your project.

### Common commands

```bash
# Create package.json interactively
npm init

# Create package.json with defaults
npm init -y

# Install a package as a production dependency
npm install react react-dom

# Install a package as a development dependency
npm install -D vite

# Install all dependencies already listed in package.json
npm install

# Run a script defined in package.json
npm run dev
```

For a new React project, the recommended quick start is usually to scaffold a Vite project instead of manually wiring every package; see Section 4.

## 2. `package.json`, `package-lock.json`, and `node_modules`

- **`package.json`** describes the project, its scripts, and the dependencies it declares.
- **`package-lock.json`** records the resolved dependency tree and versions so installs are more reproducible. Commit it to source control for an application.
- **`node_modules/`** contains the installed packages. It is generated by npm and normally should not be committed to Git.

### `dependencies` vs `devDependencies`

```json
{
  "dependencies": {
    "react": "...",
    "react-dom": "..."
  },
  "devDependencies": {
    "vite": "..."
  }
}
```

- **`dependencies`** are packages the application needs at runtime.
- **`devDependencies`** are packages used for development, testing, linting, or building. Vite is a build tool, so it normally belongs in `devDependencies`.

The final production bundle can include code from packages declared as dependencies; `dependencies` does not mean that the browser downloads the package directly from `node_modules` at runtime.

## 3. Semantic versioning

A package version is commonly written as `MAJOR.MINOR.PATCH`:

- **Major**: may include breaking changes.
- **Minor**: adds functionality while maintaining the package's stated compatibility rules.
- **Patch**: bug fixes that should not introduce breaking changes.

In `package.json`, version prefixes describe allowed version ranges:

- `"1.2.3"`: exact version.
- `"^1.2.3"`: allows compatible minor and patch updates, while staying below `2.0.0` for a `1.x` package.
- `"~1.2.3"`: allows patch updates within the `1.2.x` line, staying below `1.3.0`.

There are special rules for `0.x` versions, so `^` is not always simply “anything up to the next major”. The lockfile records the versions resolved for a particular installation.

## 4. Vite

**Vite is a frontend build tool.** It provides a development server with fast updates and a production build command that prepares optimized assets for deployment. It is more than just a bundler.

Other tools in the same broad space include webpack and Parcel.

### Create a React + Vite project

```bash
npm create vite@latest my-react-app -- --template react
cd my-react-app
npm install
npm run dev
```

Follow any prompts shown by the scaffolder. The terminal prints the local development URL.

### Common scripts

A Vite project typically has scripts like these in `package.json`:

```json
{
  "scripts": {
    "dev": "vite",
    "build": "vite build",
    "preview": "vite preview"
  }
}
```

- `npm run dev` starts the development server.
- `npm run build` produces the production build, typically in `dist/`.
- `npm run preview` locally serves that production build so you can check it before deployment. It is not a production hosting server.

Vite uses modern tooling to transform modules and JSX and to create production assets. The exact implementation can evolve between Vite versions, so avoid memorizing “Vite is just esbuild” or “Vite is only a bundler”.

## 5. Typical project structure

```text
my-react-app/
├── index.html
├── package.json
├── package-lock.json
├── node_modules/
└── src/
    ├── main.jsx
    ├── App.jsx
    └── index.css
```

- `index.html` is the HTML entry point Vite serves during development.
- `src/main.jsx` bootstraps React and mounts the application.
- `src/App.jsx` usually contains the root application component.
- `src/index.css` contains shared styles.

A typical `index.html` contains a module script pointing to the React entry file:

```html
<div id="root"></div>
<script type="module" src="/src/main.jsx"></script>
```

`type="module"` tells the browser to treat the script as an ECMAScript module. Vite also uses this entry to process the application during development and build.

## 6. Mounting a React application

A typical `src/main.jsx` looks like this:

```jsx
import { StrictMode } from "react";
import { createRoot } from "react-dom/client";
import App from "./App.jsx";
import "./index.css";

createRoot(document.getElementById("root")).render(
  <StrictMode>
    <App />
  </StrictMode>
);
```

- `createRoot()` creates a React root attached to the DOM element with ID `root`.
- `.render()` tells React what to display in that root.
- `StrictMode` enables extra development checks. For example, it can make components render again or Effects run an extra setup/cleanup cycle in development to help find bugs. These checks are not extra production behavior.

## 7. ES modules: `export` and `import`

Modules let you split code into separate files and explicitly share values between them.

### Default export

A module can have **one default export**:

```jsx
// App.jsx
export default function App() {
  return <h1>Hello React</h1>;
}
```

Import it without braces; the local name can differ from the exported name:

```jsx
import App from "./App.jsx";
```

### Named exports

A module can have multiple named exports:

```js
// helpers.js
export function add(a, b) {
  return a + b;
}

export const appName = "React Practice";
```

Import named exports using braces and the exported name:

```js
import { add, appName } from "./helpers.js";
```

You can combine a default export and named exports in one module, but prefer an export style that keeps the file easy to understand.

### Component naming

React components should start with a capital letter so JSX can distinguish them from built-in HTML tags:

```jsx
<App />       // React component
<button />    // built-in HTML element
```

Using filenames such as `App.jsx` for `App` is a common convention, not a JavaScript requirement.

## 8. Key takeaways

1. Use npm to install packages and run scripts.
2. `package.json` describes dependencies and scripts; `package-lock.json` locks the resolved dependency tree.
3. Keep runtime packages in `dependencies` and build/test tooling in `devDependencies`.
4. Vite provides both a development server and a production build.
5. For a new React app, `npm create vite@latest` is a convenient starting point.
6. Use named and default exports to organize code across files.
7. `npm run build` builds the app; `npm run preview` lets you inspect that build locally.
